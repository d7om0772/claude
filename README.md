# قوالب مونتاج بضغطة زر

قوالب فيديو جاهزة مبنية على [Remotion](https://remotion.dev). المستخدم يختار
واحداً، يعبّي تفاصيله (ألوان، شعار، نص، وسائط، صوت + SRT)، ويحصل على فيديو.
دور المحرّر — بشراً كان أو نموذجاً — **تعديل القالب لا إنشاؤه من الصفر**.

المعرض قسمان:

| القسم | ما هو | `kind` |
|---|---|---|
| **القوالب** | نموذج كامل: عدة لقطات على تايم لاين واحد، بمشاهد وكابشن وصوت | `template` |
| **اللقطات** | وحدة واحدة قائمة بذاتها تُستعمل مفردة | `shot` |

الاثنان يتشاركان عقداً واحداً ومحرّراً واحداً؛ الفرق حقلٌ في `template.json`
لا مجلدان منفصلان، فإضافة أيٍّ منهما تبقى سطراً واحداً في السجلّ.

## التشغيل

**للاستعمال العادي** (عملية واحدة، منفذ واحد، رندر كامل):

```bash
npm install
npm run build
npm start          # ثم افتح http://localhost:5174
```

**للتطوير** (إعادة تحميل حيّة للواجهة):

```bash
npm run dev        # الواجهة على 5173 وخادم الرندر على 5174
npm run ui         # الواجهة وحدها (معاينة بلا رندر)
npm run server     # خادم الرندر وحده
npm run studio     # استوديو Remotion (للتطوير على القوالب نفسها)
npm run previews   # يعيد توليد عيّنات المعرض
npm run format     # تنسيق المصدر
```

## النشر

المشروع يعمل بعملية واحدة تقدّم الواجهة وتُنفّذ الرندر على منفذ واحد:

```bash
npm run build && npm start
```

`Dockerfile` جاهز لأي مضيف حاويات. التفاصيل والموارد المطلوبة والنقاط التي
تحتاج قراراً قبل النشر العام في [`DEPLOY.md`](DEPLOY.md).

## الواجهة

شاشتان:

**المعرض** — بطاقة لكل قالب فيها عيّنة فيديو تعمل عند المرور بالمؤشّر، فيرى
المستخدم القالب متحرّكاً قبل اختياره. العيّنات في `public/previews/` وتُولَّد
بـ `npm run previews` بصيغتين: `mp4/H.264` و `webm/VP8`. الصيغتان مقصودتان —
‏H.264 ترميز احتكاري تفتقده بعض بُنى Chromium على لينكس فتظهر العيّنات فارغة
بلا أي خطأ شبكة، وwebm غير مدعوم على سفاري الأقدم.

**المحرّر** — معاينة حيّة عبر `@remotion/player` إلى جانب حقول التخصيص.
**الحقول ليست مكتوبة يدوياً**: `src/lib/schema-introspect.js` يستنطق
`schema.js` الخاص بالقالب ويشتقّ منها الحقل المناسب — منتقي لون لـ `zColor`،
شريط انزلاق للأرقام المحدودة، قائمة للـ enum، رافع ملفات للأصول، محرّر أسطر
لمصفوفات الكائنات. إضافة حقل إلى قالب تُظهره في الواجهة بلا تعديل أي كود واجهة.

### الرندر وقائمة الانتظار

`npm run dev` يشغّل الواجهة على `5173` وخادم الرندر على `5174`، والوكيل يربطهما
على أصل واحد. زرّ **رندر** داخل المحرّر يرفع الملفات ثم ينشئ مهمة.

**تقدر تشتغل على قالب ثانٍ بينما الأول يُرندر** — وهذا ليس ميزة أُضيفت بل نتيجة
مكان الحالة: الرندر يجري في الخادم، والواجهة لا تحمل منه إلا معرّف المهمة،
وقائمة المهام تعيش في `App` فوق الشاشتين. فالرجوع للمعرض واختيار قالب آخر لا
يمسّ المهام الجارية لأن حالتها ليست داخل المحرّر أصلاً.

مهمة واحدة تُنفَّذ في كل لحظة وما عداها ينتظر: الرندر يشبع المعالج، وتشغيل
مهمتين معاً يبطئ الاثنتين ولا يقصّر الزمن الكلي.

| المسار | العمل |
|---|---|
| `GET /api/health` | هل الخادم يعمل — تفحصه الواجهة لتعرف إن كان الرندر متاحاً |
| `POST /api/assets` | يرفع ملفاً إلى `public/uploads` ويعيد مساره |
| `POST /api/jobs` | ينشئ مهمة رندر |
| `GET /api/jobs` | حالة كل المهام |
| `GET /api/jobs/:id/file` | تنزيل الناتج |

الملفات المرفوعة تُحفظ داخل `public/` لأن `staticFile` في القوالب يحلّ المسارات
النسبية من هناك، فيصير المسار المعاد صالحاً للرندر بلا تحويل. والاسم يُولَّد من
جديد ولا يُشتقّ من اسم الملف الوارد.

حزمة القوالب تُبنى مرة واحدة عند إقلاع الخادم وتُعاد لكل المهام — بناؤها لكل
مهمة يضيف عشرات الثواني بلا فائدة.

### تحرير الكابشن

في القوالب التي يعرض فيها الكابشن كلمات الفيديو — `paper-karaoke-captions`
و `thmanyah-word-reveal-vertical` — يكون حقل «النص الرئيسي» **احتياطياً**:

```js
if (captions.length > 0) return captions;   // الكابشن يغلب
```

وقيمهما الافتراضية تأتي بكابشن ممتلئ (٦ و٤ مقاطع)، فتعديل النص الرئيسي فيهما
لا يغيّر شيئاً. لذلك الكابشن **قابل للتحرير في الواجهة** لا للعرض فقط: نص كل
مقطع وتوقيتاه، مع إضافة وحذف. و«مسح الكل» يُفرغه فيظهر النص الرئيسي بدله.

### الرندر داخل المتصفح

حين لا يكون خلف الصفحة خادم — كالنسخة المنشورة — يظهر زرّ **«رندر في
المتصفح»**: الفريمات تُرسم في الصفحة نفسها وتُرمَّز عبر **WebCodecs** بلا أي
شبكة، ثم يُسلَّم الملف للمستخدم.

`src/ui/web-render.js` يجرّب أفضل صيغة ينزل: `mp4/h264` أولاً لأنه الأوسع
قبولاً، ثم `webm/vp9`، ثم `webm/vp8`. المستخدم يحصل على أفضل ما يدعمه متصفحه
بدل رسالة فشل — كثير من بُنى Chromium تفتقد ترميز h264 الاحتكاري فتنزل إلى
webm تلقائياً.

التسليم في `src/ui/save-file.js` بمسارين: داخل صفحة artifact منشورة تمنع
البيئة الصفحةَ من بدء تنزيل بنفسها، فالطريق هو صلاحية `downloads` التي تعرض
تأكيداً على المشاهد وسقفها **١٦ ميغابايت**. وخارجها رابط تنزيل عادي.

الرندر في المتصفح أبطأ من الخادم ويشغّل تبويب المستخدم، لذلك يبقى صريحاً لا
تلقائياً، ويظهر زرّ الخادم بدله متى كان متاحاً.

### الصوت المرجعي والتزامن

قسم «الصوت والتزامن» يستقبل ملف SRT وملف الصوت معاً، ثم يفحص تطابقهما قبل
الرندر لا بعده:

- **فرق النهاية**: يقارن آخر `endMs` بطول الصوت. لو تجاوزه الكابشن نبّه إلى
  أنه سيُقتطع، لأن المدة تُشتقّ من الصوت.
- **مستوى التقطيع**: القوالب الموسومة `word-by-word` تحتاج SRT على مستوى
  الكلمة. لو كان متوسط الكلمات في المقطع أعلى من ذلك نبّهت الواجهة، لأن
  إطعامها SRT على مستوى الجملة يعرض الجملة كلها ككلمة واحدة عملاقة.
- **التداخل**: المقاطع المتداخلة تُقصّ تلقائياً عند التحويل، والواجهة تخبر
  بذلك بدل أن يحدث بصمت.

الملفات المرفوعة تبقى في المتصفح كـ `blob:` ولا تُرفع لأي خادم. مسار `blob`
بلا امتداد، والقوالب تميّز الفيديو من الصورة بالامتداد — فتُلحق الواجهة
`#.mp4` ونحوه بالرابط: الجزء بعد `#` لا يدخل في البحث عن الـ blob فيبقى
الرابط صالحاً، ويكفي أدوات الاكتشاف. بدونه كان أي فيديو مرفوع يُعرض كصورة
ثابتة ولا تُحتسب مدّته.

الرندر:

```bash
npx remotion render paper-card-kinetic-line out/video.mp4 --props=examples/props.json
```

## اللغة

المشروع **JavaScript خالص (JSX)** بلا TypeScript ولا خطوة ترجمة: `node`
يشغّل الخادم والأدوات مباشرة، وVite يترجم JSX للواجهة فقط.

نتيجتان لهذا الاختيار تستحقّان الانتباه:

- **الاستيراد النسبي يحتاج امتداداً صريحاً** (`./foo.js` لا `./foo`) لأن
  Node ESM لا يخمّن الامتدادات.
- **Node لا يفهم JSX.** لذلك الخادم لا يستورد `registry.js` (فيه مكوّنات
  React) بل `template-meta.js` الذي يحمل الميتاداتا وحدها. الرندر الفعلي
  يجري داخل حزمة Remotion في المتصفح، فالخادم لا يحتاج المكوّنات أصلاً.

التحقق من الأنواع لم يعد موجوداً، فاعتمد على `zod` — وهو فحص وقت تشغيل لا
وقت ترجمة، ولذلك بقي عاملاً كما هو: القيم الخارجة عن حدود الـ schema تُرفض
عند الرندر، وتوليد حقول الواجهة منها لم يتأثر.

## عقد القالب

كل قالب مجلد مستقل تحت `src/templates/<id>/` فيه أربعة ملفات، ولا شيء غيرها:

| الملف | الدور |
|---|---|
| `Template.jsx` | المكوّن — التصميم والحركة. **صفر قيم ثابتة**: كل شيء يصل عبر props |
| `schema.js` | zod schema + `defaultProps`. منه تتولّد واجهة التخصيص تلقائياً |
| `template.json` | ميتاداتا شاشة الاختيار: الاسم، `kind` (قالب أو لقطة)، المقاس، المدة، الوسوم |
| `README.md` | خريطة الطبقات، جدول التايم لاين، الثابت مقابل المتغيّر، حدود المحتوى |

الاستثناء الوحيد من الاستقلال: **الخط**. تحميله في `src/lib/fonts.js`.
الخط أصل على مستوى المشروع لا
على مستوى القالب، وعزله يمنع تكرار `delayRender` وتسجيل نفس `FontFace` مرتين.

**إضافة قالب جديد = مجلد جديد + سطر واحد في `src/lib/registry.js`.**
السجلّ يرفض المعرّفات المكرّرة عند التحميل، لأن معرّفين متطابقين يعنيان
Composition واحداً يطغى على الآخر بصمت فيختفي قالب كامل بلا رسالة خطأ. لا `Root.jsx`
ولا أي ملف آخر يحتاج تعديلاً — الـ Compositions تتولّد من السجلّ.

## الصوت المرجعي و SRT

القالب **لا يعرف شيئاً عن SRT**. يستقبل مصفوفة `{ text, startMs, endMs }` جاهزة،
والتحويل كله يحصل خارجه في `src/lib/srt.js` — فيبقى القالب نقياً ويشتغل مع أي
مصدر كابشن (SRT، VTT، تفريغ آلي).

```bash
npm run srt -- examples/sample.srt                      # يطبع الـ JSON
npm run srt -- examples/sample.srt out.json             # يكتبه في ملف
npm run srt -- examples/sample.srt --props props.json   # يحقنه في ملف props
```

المحوّل يتعامل مع: BOM، نهايات CRLF، رقم المقطع المفقود، النقطة بدل الفاصلة في
الطابع الزمني، النص متعدد الأسطر، وسوم التنسيق `<i>`، إحداثيات الموضع، وتداخل
المقاطع (يُقصّ تلقائياً حتى لا يختفي مقطع بلا سبب ظاهر).

تفصيل مهم: `paper-card-kinetic-line` يتوقع كابشن **على مستوى الجملة**، بينما
`paper-karaoke-captions` و `thmanyah-word-reveal-vertical` يتوقعانه **على مستوى
الكلمة** (كل مقطع = كلمة واحدة).
المحوّل يخدم الحالتين — الفرق في تقطيع ملف SRT نفسه.

## مدة اللقطة

تُشتقّ من المحتوى في `src/lib/duration.js`، والقاعدة **أطول ما أُرفق**:

| المصدر | مساهمته |
|---|---|
| التعليق الصوتي | طوله بالكامل |
| الفيديو المرفق | لحظة بدء عرضه + طوله |
| الكابشن | آخر `endMs` + ذيل السكون |
| لا شيء | `fallback` الخاص بالقالب |

كل أصل يرفعه المستخدم محتوىً أراد رؤيته أو سماعه كاملاً، فاقتطاع أيٍّ منه
بصمت خللٌ لا ميزة. حين يُرفق أصل واحد فقط تساوي المدة مدّته بالضبط.

«لحظة بدء العرض» مهمة في القوالب التي لا يظهر فيها المقطع من البداية:
في `paper-card` يظهر بعد القطع، فمدّته تُضاف إلى لحظة القطع لا إلى بداية
اللقطة، وإلا اقتُطع آخره بمقدار زمن المشهد النصي.

الوسائط تُحتسب فقط إن كانت فيديو — الصورة الثابتة لا مدة لها.

## جماليات خط ثمانية

كل القوالب تستعمل خط ثمانية سيرف ديسبلاي، بوزنيه المتاحين فقط:
**Black‏ 900** للتأكيد و**Medium‏ 500** لما دونه. لا يوجد Bold في العائلة،
واستعماله لو وُجد يضعّف التباين الذي تقوم عليه هذه القوالب.

خصائص OpenType التزيينية (`salt` للأحرف المرسلة و`ss03` للكشيدة) **أُزيلت من
كل القوالب**: الرندر داخل المتصفح يرسم النص عبر Canvas 2D، وهي واجهة لا تعرف
`font-feature-settings` أصلاً، فكانت هذه الأشكال تظهر في المعاينة وتغيب عن
الفيديو الناتج. ما يبقى من الدليل هو ما يصمد في المسارين: العائلة، والوزنان،
وقاعدة التباين بينهما.

## الخطوط

خط ثمانية Serif Display — **عائلة واحدة بوزنين**: Black‏ (900) للسطر الضخم،
Medium‏ (500) للسطر الصغير والكابشن. الأصل `.otf` ومحوّل إلى `woff2`.

الملفات غير مرفوعة في المستودع (مستثناة في `.gitignore` احتراماً لرخصة ثمانية
التي تمنع إعادة الاستضافة العلنية). راجع `public/fonts/README.md` — بدونها
القالب **يشتغل** لكن بخط بديل، مع تحذير واضح في السجل، والضبط يختلف عن التصميم
الأصلي لأن قياسات `measureText` تتغيّر فتنزاح محطات الوقوف.
