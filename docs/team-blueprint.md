# نموذج "فريق وكلاء" على Claude Code — مأخوذ من نظام تيربو

هذا الملف يشرح الطريقة اللي انبنى فيها نظام تيربو، وفي آخره برومبت جاهز تعبيه وترسله في جلسة جديدة عشان تبني نفس النموذج لشغل ثاني.

---

## ١. الفكرة في سطرين
**مستودع GitHub واحد هو "المكتب":** فيه دستور الفريق (`CLAUDE.md`)، وملف تعليمات لكل موظف (وكيل)، وملف تعليمات لكل مهمة مجدولة، وجدول حالة لكل قطعة شغل.
**مهام مجدولة تصحى لحالها** في جلسة سحابية دائمة، كل وحدة تقرا ملفها وتشغّل الوكلاء، وتحفظ كل خطوة في المستودع.

## ٢. مكونات النموذج
| المكوّن | وش هو في تيربو | ليش مهم |
|---|---|---|
| **المستودع = الذاكرة الوحيدة** | `d7om0772/claude` على `main` | الحاوية السحابية تنمسح؛ اللي ما انحفظ (commit + push) يضيع |
| **الدستور `CLAUDE.md`** | الهدف، الجمهور، القواعد الثابتة، خريطة الملفات، دور "المدير" | كل جلسة ومهمة تقرأه أول شي، فالكل يمشي على نفس القواعد |
| **الوكلاء** `.claude/agents/*.md` | كاتب، مدقق، صانع فيديو، ناشر، محلل، محرر أخبار | كل موظف له تعليمات وأدوات خاصة فيه، ويرجّع ملخص قصير |
| **ملفات المهام** `schedules/*.md` | write · produce · publish · rescue · analyze · news | برومبت المهمة ثابت ("اقرأ CLAUDE.md ثم نفّذ schedules/X.md")، فتغيّر الشغل بتعديل الملف بدون ما تلمس المهمة |
| **جدول الحالة** `content/calendar.md` + أداة `cal.py` | فكرة ← سكربت ← معتمد ← فيديو جاهز ← مجدول ← منشور | كل مهمة تعرف وين وقف الشغل وتكمّل منه |
| **أدوات ثابتة** `scripts/` | `day_info` (التواريخ والمواعيد)، `cal` (الجدول)، `git_save` (حفظ)، `bootstrap` (تجهيز البيئة) | الأشياء المتكررة بالكود بدل ما يعيد الذكاء الاصطناعي حسابها كل مرة |
| **الملفات المرجعية** `brand/` | حزم التصميم، قواعد النطق، الهوية | "الكلمة الأخيرة" في الجودة؛ الوكلاء يرجعون لها |
| **جلسة المشغّل** | جلسة سحابية دائمة فيها المستودع وكل الموصلات | المهام المجدولة تصحى فيها (انظر الدروس) |
| **المدير** | أي جلسة تفتحها أنت على المستودع | أي تعديل يمر عليه: يعدّل الملف + يسجّل في `CHANGELOG.md` + يحفظ |
| **المتابعة** | صفحة "متابعة تيربو" + `schedules/runs.md` + نسبة استهلاك الحد | تعرف وش صار بدون ما تفتح الجلسات |

## ٣. قواعد التشغيل اللي خلّت النظام يمشي لحاله
1. **لا تسأل ولا تنتظر** في المهام المجدولة: خذ القرار المعقول وسجّله.
2. **كمّل الناقص أول** قبل الشغل الجديد.
3. **احفظ بعد كل خطوة** على `main`.
4. **الفشل ما يوقف الخط:** سجّل السبب وكمّل الباقي.
5. **مهمة إنقاذ** تمر نص اليوم وتكمّل أي شي ناقص.
6. **مدقق مستقل** قبل أي نشر، بقواعد مكتوبة (مصادر، أرقام، تواريخ).
7. **احتياطي لكل خدمة خارجية** (مثال: صوت فهد ← لو الرصيد خلص ← Gemini).
8. **آخر سطر في كل مهمة:** ملخص في سجل التشغيل + تحديث صفحة المتابعة.

## ٤. خطوات البناء بالترتيب
1. **برومبت إعداد واحد مفصّل** (القالب تحت): الهدف، الجمهور، الموظفين، المواعيد، الأدوات، الممنوعات.
2. **مستودع GitHub** فاضي ومربوط بـ Claude Code.
3. **بيئة سحابية** (Environment): المفاتيح كمتغيرات بيئة (ما تنكتب في أي ملف)، وسكربت إعداد يثبت الأدوات.
4. **الموصلات** في claude.ai (مثل Schedulin، Cloudinary، ElevenLabs...).
5. **جلسة الإعداد** تبني: `CLAUDE.md`، الوكلاء، ملفات المهام، الأدوات، جدول الحالة، وتجرب السلسلة كاملة **بدون نشر**.
6. **الملفات المرجعية** (قوالب، أمثلة، حزم تصميم) ← تتحول لقوالب ثابتة.
7. **جلسة المشغّل + المهام المجدولة** مربوطة فيها.
8. **صفحة متابعة** + سجل التشغيل.
9. **بعدها كل تعديل** من جلسة "مدير" بكلمة منك.

## ٥. دروس تعلمناها (وفّر على نفسك الوقت)
- **المهام المجدولة بخيار "جلسة جديدة كل مرة"** تنشأ في حسابك **بدون المستودع وبدون الموصلات**. الحل اللي اشتغل: **جلسة مشغّل دائمة** فيها المستودع والموصلات، والمهام مربوطة فيها. **لا تأرشفها.**
- **أسماء أدوات الموصلات** تختلف من جلسة لجلسة (بالاسم أو بمعرّف). لا تحصر أدوات الوكيل بقائمة أسماء؛ خلّه يرث كل الأدوات ويبحث عن الأداة باسمها.
- **حد الاستخدام** (5 ساعات وأسبوعي) هو العائق الحقيقي. سجّل نسبته بعد كل مهمة، وخفّف الشغل لو قرب.
- **الجوال:** بعض أنواع الصفحات (مثل لوحة Data) تحتاج iOS حديث؛ صفحة HTML بسيطة تفتح دايماً.
- **الخدمات الخارجية** ممكن تخلص أرصدتها أو تحجب التنزيل الآلي: جهّز بديل لكل وحدة.
- **ابدأ بوتيرة خفيفة** وارفعها بالتدريج (تيربو: فيديو باليوم ← 2 ← 3).
- **"المدير"** يسجّل كل تعديل في `CHANGELOG.md` عشان تعرف ليش تغيّر أي شي.

لا تنتظر موافقتي على أي شي. احفظ كل شي على الفرع الأساسي (main) بعد كل خطوة، وفي النهاية عطني ملخص قصير.
